# 贝报切片助手（bella-live-clip）

当前版本为 `2.13.14`。在浏览器里剪辑 B 站投稿视频和直播回放，导出 MP4。

支持普通投稿视频，以及贝拉、乃琳、嘉然、心宜、思诺的本场直播回看与近 14 天历史回放。

## 安装

1. 安装 Tampermonkey。
2. 点击 [立即安装](https://share.bellaris.fans/bella-live-clip.user.js)。
3. 在同一个浏览器登录 B 站，刷新页面，点击右下角的剪辑图标。

默认快捷键为 **Alt＋Shift＋C**。导出需要 Chrome 或 Edge。

## 使用

1. 在投稿视频页、直播间或任意 B 站页面打开面板，选择要剪辑的内容。
2. 拖动时间轴选择起止位置，或直接输入时间。
3. 选择“原画”（不重新编码，起止点对齐到关键帧）或“精确”（按所选位置裁剪，头尾重新编码），点击“导出”。
4. 直播／历史回放选区可在“原画 / 精确 / 弹幕”中选择导出方式；选择“弹幕”即可压制弹幕，选择会保存。压制会重新编码所选画面，分辨率不变；录像、弹幕和表情按需供给，边下载边压制，无需等完整选区准备完毕。表情读取或解码失败重试后仍不可用时，以原文字显示；归档读取失败仍会停止并提示。
5. 想保存一整段直播，打开“整场”开关；目前整场暂不支持压制弹幕。

| 操作 | 按键 |
|---|---|
| 移动 5 秒 / 1 秒 / 0.1 秒 | 方向键 / Shift＋方向键 / 逗号和句号 |
| 播放或暂停 | 空格 |
| 设为开始 / 结束 | I / O |

导出期间请保持页面打开。

更多行为说明见 [详细说明](docs/details.md)，版本变化见 [更新记录](CHANGELOG.md)。

## 权限与边界

- 使用当前浏览器登录态，是否可回放取决于账号和主播权限。
- 历史场次来自平台近 14 天回放接口，不是永久录像仓库。
- 登录态请求仅发往 B 站直播 API 和投稿 API；视频服务器、日程、头像资料、公开弹幕与表情归档（data.bellaris.fans）及更新检查为匿名请求。投稿接口通过网页自身的登录会话请求；预览直接显示 B 站正在播放的画面，缩略图使用最低可用 H.264 画质，精确导出使用最高可用 H.264 画质与 AAC 音轨。投稿媒体优先从接口给出的常规 CDN 地址读取，不扩大到任意域名权限。
- 投稿功能支持 BV/av 普通视频及当前分 P，不包括番剧、电影、本地文件、字幕或弹幕烧录、多段拼接和批量分 P 下载；不绕过账号访问权限。
- 公开版不发布内容、不创建投稿草稿；Preview 登录创作台后可确认投稿（见下文）。脚本不保存 Cookie、签名媒体链接或视频到扩展存储。
- 接口并非承诺稳定的公开 API，平台改版后可能需要更新。

## 构建渠道（维护者）

公开版提供剪辑与导出，Preview 另提供创作台登录、共享轴表和投稿。

| 命令 | 产物 | 用途 |
|---|---|---|
| `npm run build` | `bella-live-clip.user.js` | 公开版：剪辑与导出 |
| `npm run build:preview` | `bella-live-clip.preview.user.js` | Preview：另含登录、共享轴表与投稿 |
| `npm run build:all` | 上述两个文件 | 同时构建两个渠道 |

两个渠道共用 `src/header.txt` 的 `x.y.z` 版本号；任一渠道功能变化时都应按现有规则递增版本。Preview 的名称为 `贝报切片助手 Preview`，有独立的脚本标识和更新地址 `/bella-live-clip.preview.user.js`，内置检查更新也使用本渠道地址。切换渠道时请在 Tampermonkey 中停用另一版，避免同时运行。

Preview 专属功能使用构建常量包裹；普通构建会在压缩时移除该分支。若模块带有初始化副作用，将动态导入放在分支内，避免顶层导入使 Preview 专属代码进入公开版：

```js
if (typeof __PREVIEW__ !== 'undefined' && __PREVIEW__) {
  const {startPreviewFeature} = await import('./preview/feature.js');
  startPreviewFeature();
}
```

示例应放在异步函数内。未注入构建常量的测试和开发入口默认不开启 Preview 专属功能。

### Preview 投稿与简单封面

- 直播／回放选区的「投稿」与「导出」并列，沿用当前原画／精确／弹幕模式，后台写入浏览器临时文件，前台填写标题、固定与自选标签、简介和封面。标题必填且最多 80 字，标签合计 1–12 个、每个最多 20 字。创作台必须先配置投稿账号和分区，否则不会开始导出。
- 简介按创作台模板填入日程匹配的直播标题和排期日期；匹配失败时使用直播标题与开播日期（UTC+8），署名来自创作台身份。简介可编辑。
- 封面默认取选区中点，可拖动滑块按需选帧、拖动／缩放 16:9 裁剪框，添加一行文字并调整字号、颜色、描边和位置。输出 1920×1080 JPEG（质量 0.9），上传为创作台封面。只提供一张横版封面，未添加独立 4:3 封面编辑。
- 上传从临时文件逐片读取，经脚本管理器匿名直传 UPOS，失败时按创作台配置回退 COS。遇上传安全验证时，前往 [创作台](https://studio.bk0717.com) 完成验证，再在插件点击「重试」。不在插件中处理验证码。
- 上传完成且点击「确认投稿」后自动提交；提交前可随时取消，停止导出／上传并清理临时文件。发出投稿请求后不再提供取消；失败可重试，网络响应丢失时保留同一请求 ID 防止重复稿件。成功显示 BV 和复制按钮，并加入配置的合集；合集失败单独重试，不重新投稿。
- 从轴表设定选区时会显示关联轴，可解除关联；提交前再点另一条轴，会取消旧选段的任务、换用新选段，保留已填写的标题／标签／简介并重新确认。服务端将成功 BV 写回关联轴。
- 关闭再打开面板保留当前任务与表单；刷新或关闭网页无法续传，会先提示正在处理。成功或取消后删除临时成品；上传／投稿失败时保留临时文件以便重试。公开版不包含这些新增界面与接口，保留既有创作台上传桥接功能。

### Preview 登录与共享轴表

- Preview 需先点击面板里的「登录」，在 [贝报创作台](https://studio.bk0717.com/plugin/link) 领取插件令牌；连接成功后原面板自动继续。未登录或创作台返回 401 时，剪辑、导出、直播截图和记轴均不可用。设置显示登录身份并可退出；退出只清除本地令牌。
- 默认 **Alt＋Shift＋M** 记轴（设置可改，不能与面板快捷键冲突）。直播页关闭面板时也可使用；打开面板时使用当前直播／回放的房间。按下时立即保存校正后的 UTC 时间，不扣观看延迟。Enter 保存备注，Esc 留空，12 秒未确认也自动保存；备注最多 200 字。
- 轴先保存在脚本管理器本地队列，显示「未同步」，网络恢复、下次打开面板或退避重试时使用同一 UUID 补传。队列不会因退出登录而删除；重新登录后继续同步。短房间号首次需要联网解析，之后可使用本地缓存离线记轴。
- 当前场次轴表每 10 秒刷新（面板关闭或页面不可见时暂停），支持编辑时间／备注、删除与撤销、查看历史及已关联的 BV 链接。并发修改冲突会刷新列表并提示重试。补记如 `21:13:40 跑调` 按 UTC+8 解释，优先取当前场次内的日期，否则取最近的过去时刻。
- 点击轴默认选择前 30 秒到后 15 秒并跳到入点，余量可在设置里调整；时间轴显示轴标记。回放未覆盖出点时提示「等待回放」，重新请求直播录像快照；断流空档对齐最近画面，跨分段选区限制在轴所在分段并提示分段导出。
- Preview 新增到 `studio.bk0717.com` 的匿名 Bearer 请求及 GM 存储监听／键枚举权限；插件令牌存于 `biliClip.` 命名空间，不发送到 B 站或诊断服务。公开版不包含登录与轴功能，也不新增这些权限。

`npm run verify` 检查两个渠道。公开版产物继续提交到仓库，Preview 产物由构建生成、不提交。主分支发布流程会构建并上传两版；本地构建不发布。`--release` 只控制日志服务配置注入，可用于任一渠道，例如 `npm run build:preview -- --release`。Preview 是功能渠道，不是访问控制，发布后的文件可通过其地址访问。

## 日志服务（维护者）

仓库包含可供多个项目使用的 Cloudflare Worker + D1 日志服务，支持正常运行及导出性能上报、按来源去重、网页筛选查看和 JSONL 下载。发布方式见 [日志服务说明](server/logs/README.md)。

构建和发布分别生成、上传压缩的公开版及 Preview 脚本，每个渠道的检查更新和安装使用各自同一地址。

生产部署只读取 GitHub Actions Secret `LOG_SERVICE_CONFIG`，不在仓库中保存实际账户、Worker、数据库、域名或令牌配置。资源及域名绑定由维护者预先完成；部署流程只检查并更新已有 Worker 和数据库，不读取、验证或修改域名，也不自动创建替代资源。发布构建从同一个 Secret 注入公开接收地址和对应网络权限，仓库中的构建不含实际地址；管理凭据不会进入插件。

预览截图浏览器验证：运行 `npm run serve`，打开 `http://127.0.0.1:8765/?screenshot`，选择场次后移入预览并点击相机，再移出预览。测试页应显示 `hoverShown`、`leaveHidden`、`png` 和 `nativeSize` 均为 `true`，并实际下载原尺寸 PNG。

弹幕性能对照：运行 `node tools/scripts/benchmark-danmaku.mjs`（需要 FFmpeg 和 Playwright Chromium）。对同一 1080p/30fps 素材比较 2.13.1 合成器与当前实现，预热后交替测量三次，输出空弹幕、固定弹幕和滚动弹幕的中位耗时，以及各次的 `metrics` 阶段统计。旧基线保留原字号和描边，当前实现采用更小字号及描边阴影，因此结果也包含外观变化的开销。编码提交等待与下一帧读取、准备、绘制会重叠，各阶段累计耗时不能直接相加为导出总耗时。测量仅覆盖解码、合成、编码和内存封装，不包含网络或写盘，不能当作真实导出的提速承诺。`npm run test:e2e` 另外验证当前外观与全帧参考渲染逐像素一致、动态表情、原尺寸和 AAC 音频保留。

弹幕流水线验证：`node --test tools/tests/e2e/streaming.e2e.mjs` 会故意阻塞后续分片、写盘和后续表情，检查前段仍可编码、尾部探测不阻塞启动、下载能响应下游压力、取消能够清理资源。测试还覆盖未使用预取失败、需求重试及缓存淘汰，并对照旧流程的视频帧时间和 AAC 音频包。

1080p 流程复测：`STREAMING_TEST_1080P=1 node --test --test-name-pattern="encoding begins" tools/tests/e2e/streaming.e2e.mjs`。默认流水线回归使用较小素材以缩短运行时间。

弹幕阶段测量：`onProgress` 和导出结果包含本地 `metrics`，记录首包延迟、取帧等待、弹幕准备、合成、编码提交、合封和写盘。各阶段会重叠，不能直接相加；`encodeSubmit` 含编码队列等待，`sampleWait` 含上游素材等待，均不代表纯 CPU 耗时。硬件偏好也不代表实际硬件使用情况。
