# Design
Use a dedicated src/schedule.js exporting ScheduleService(request) and parser/matcher helpers. enrich(records, {signal, refresh=false}) returns records copied with schedule:null or {type, participants:[{id,name,color,avatar}]} and a failed boolean at result level: {records, failed}. Only rooms 22632424,22637261,22625027 use schedules. Fetch months covering start ± 30 minutes in Beijing so boundaries match. Match only unique nearest event within 30 minutes in the same room; equal-distance ambiguities yield no match. Ignore planned duration for actual duration. Parse ICS folded lines and escaped description text, UTC and Asia/Shanghai DTSTART; cancelled events excluded. Never replace original title. Monthly successes cached for one hour; refresh bypasses cache, errors not cached. Participant profile faces retrieved anonymously from verified Bilibili live_user/v1/Master/info?uid=. Portrait requests cached; failures yield null avatars. App loads recordings immediately; enrichment is separately cancelled on navigation/close/refresh; late responses cannot change current member/page. UI uses textContent, small circular avatars with icon fallback, original title and time/duration metadata; no cover or visible participant names. Accessible names retain participant identification. No external credentials.
