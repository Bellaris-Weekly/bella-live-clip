# B 站直播片段下载：可行性实测

验证日期：2026-09-12 晚间（北京时间）。

结论：核心数据链路可行。使用用户提供的登录态，贝拉、乃琳、嘉然的历史回放均能获取并下载指定片段；嘉然正在进行的直播也能获取早期与近期片段。实际下载的是对应时间段的视频分片，没有下载整场录像。

本次完成接口验证与命令行原型，尚未制作或安装正式油猴脚本，也没有验证完整浏览器导出流程。

历史样片选择的是可用录像时间线的第 600—620 秒，每份仅下载 6 个相关分片。下载分片总量约 85.74 MB，媒体本身约为 21.7—25 秒；前后多出的内容来自分片边界。MB 按十进制计算。

嘉然本场直播标题为“【3D】我要当选...”，开播时间为 19:49:54。另做了两次当场录像验证：

- 开播后第 600—620 秒：7 个分片，24.26 MB，输出 23.621 秒 MP4。请求时距离该片段已经超过一小时。

因此，已证明本次嘉然直播支持回看本场更早的片段，无需从脚本启动时才开始录制。没有测出最大回溯上限，也没有测出贴近直播最新画面的最小延迟。贝拉、乃琳测试时处于轮播状态，不能冒充正在直播的样本。

原始三份历史样片、两份当场样片位于 evidence 目录；同名 result.json 记录实际字节数、分片数、视频编码与时长。replay-summary.json 保存列表摘要。文件均不包含 Cookie 或临时媒体签名地址。

## 已确认的接口链路

### 历史回放

1. GET https://api.live.bilibili.com/xlive/web-room/v1/videoService/GetOtherSliceList
   参数：live_uid、time_range=3、page、page_size。
   返回回放列表及每场的 live_key、start_time、end_time。
2. GET https://api.live.bilibili.com/xlive/web-room/v1/videoService/GetUserSliceStream
   参数：live_uid、live_key、start_time、end_time。
   **可以直接传想下载的那一段的 Unix 秒时间戳**，不必先请求整场。
3. 读取返回的 data.list 中各段 stream，对应 HLS 清单。
4. 下载清单内媒体分片，并在本地封装成 MP4。

直接传 20 秒的时间范围已实测：嘉然历史回放清单约 2 KB、6 个分片；本场早期片段约 2.4 KB、7 个分片。本次三人的媒体分片实际是带 MP4 box 的 m4s/fMP4，不能凭 HLS 名称就假定是 TS。

### 正在直播的房间

本次从直播间页面的公开初始化数据获取 room_info.live_id_str、live_start_time、uid，再调用同一个 GetUserSliceStream，也返回了可用录像。

这证明可以统一两种来源的下载流程。没有必要为了“边看边剪”先创建草稿或投稿；此次未调用任何投稿、保存草稿、发布或整场合成接口。官方“边看边剪”按钮的完整操作路径没有逐步复现，结论来自其相关录像流接口的直接实测。

live_key 应始终保持字符串：直播间数据同时提供 live_id 与 live_id_str，前者本次已呈现取整差异；正式脚本不能把字符串场次号转成 JavaScript Number。

## 油猴实现判断

建议做成 B 站页面右下角入口：直播间默认本场，其他 B 站页面默认“成员 → 历史场次”，再选择起止时间、预览并下载。位置不同只影响默认来源，下载机制可以共用。

浏览器请求具备有利条件，已用 HTTP 请求核实：

- API 对 Origin=https://www.bilibili.com 返回 Access-Control-Allow-Origin=https://www.bilibili.com、Access-Control-Allow-Credentials=true。
- HLS 清单及实测的两类媒体 CDN 返回 Access-Control-Allow-Origin=*。
- API 请求使用登录 Cookie；媒体 CDN 请求不携带账号 Cookie，只使用接口返回的地址。

由这些响应推断，油猴复用浏览器登录态、获取列表与片段数据的路线可行；但还需要实际浏览器验证，包括登录 Cookie 携带、页面限制、扩展权限、预览与保存文件。正式脚本不应硬编码本次 Cookie，也不应让用户反复复制 Cookie。

下载功能适合明确分成两种行为：

- **快速下载**：保留覆盖选区的完整分片，速度快、画质不变，前后可能多几秒。
- **精确裁剪**：仅下载相关分片后，再对局部素材处理。任意帧精确切点不能只靠无损复制承诺；浏览器内处理方式与性能还需验证。

本次 MP4 是通过本机 FFmpeg 生成的。纯油猴内的 MP4 重封装可以作为正式实现方向，不能把本次本地 FFmpeg 成功等同于浏览器端已经完成。HLS 预览以及浏览器内导出需要选定方案后分别测试。

## 重要边界

1. 历史来源是平台当前允许剪辑的回放列表，不是永久录像仓库。官方页面本次只提供“近3天 / 近7天 / 近14天”；实测使用近 14 天。不能承诺通过它下载几个月前或几年前的直播。
2. 结果依赖账号与主播的权限。本次提供的登录态对三人均成功，不代表所有账号自动有权限。
3. 开播时间、实际录像起点、分片边界并不相同。三场历史录像起点比开播晚约 13—18 秒；累计清单时长与接口时间跨度也有小幅差异。正式界面应说明时间基准，使用接口时间范围定位，再核对分片时间戳；不要只累计整场 EXTINF 来假定绝对时间完全准确。
4. 断流、跨段、参数变化、最新录像还未就绪等情况尚未验证。接口返回 list，正式实现必须按多个录像段建模，不能只读取 list[0]。
5. 列表里 alarm_info.message 出现“录像生成失败，请稍后再试”，但这三场录像流实际均可下载。不能只凭这个提示字段禁用片段下载，应该以录像流接口的实际结果判断。
6. 这些是 B 站当前网页使用的接口，不是已获稳定性保证的公开开发者 API。

## 可复现原型

本目录 probe.py 使用 Python 标准库，运行环境需安装 ffmpeg 和 ffprobe。

```sh
# 最新一场嘉然历史回放，开播后第 10 分钟附近的 20 秒
python3 probe.py --member diana --source history --offset 600 --duration 20

# 嘉然正在直播时，取本场开播后第 10 分钟附近的 20 秒
python3 probe.py --member diana --source current --offset 600 --duration 20
```

程序运行后隐藏输入 Cookie，仅存在内存，不写文件。贝拉使用 bella，乃琳使用 eileen。结果写入 output 下独立目录，包含局部 m4s、MP4 和无敏感信息的摘要。程序只覆盖本次已观测的独立 m4s 清单；不同录像段分别输出，不静默拼接不连续内容，不做精确裁剪。

此外，对原型选择不同于上述样片的开播后第 1200—1208 秒，分别验证贝拉历史录像与嘉然本场录像，检查相同机制在不同输入上可用。
