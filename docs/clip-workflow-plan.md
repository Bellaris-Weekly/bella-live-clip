# 切片工作流改造计划

2026-11-09 定稿。本文是后续实现的依据，涉及本仓库（贝报切片助手）和 bellaris-studio（贝报创作台）两个项目。

## 1. 背景与目标

我们是公益应援组织。贝拉直播后，组员把精彩片段切出来，用同一个组织账号投稿到 B 站。

现在一条切片要经过：直播前开录播 → 直播中各自记轴（东八区时间加几个字）→ 群里汇总分工 → 按时间在整份录像里找片段 → 剪映裁剪、加字幕 → 用 BiliUP 投稿。只要决定切片，整个晚上就被占用了。

**目标：** 组员只用贝报切片助手一个客户端，在里面记轴、跳到轴、切片、投稿，不再需要录播、剪映（只加字幕的切片除外）和 BiliUP。只需要裁剪的切片，直播中就能产出。

规模：每场直播 1 到 5 人参与，记 10 到 20 条轴，产出 1 到 8 条切片。所有组员都能投稿，不需要审核。

## 2. 范围

### 本期

- 插件登录：由创作台签发插件令牌；
- 记轴：记录 UTC 时间，存到创作台，所有人共享、都能编辑，每次修改都留记录；
- 轴表：插件里查看、跳转、切片；创作台网页也能查看；
- 投稿：在插件里点「投稿」，导出、上传和填写稿件信息同时进行，全部完成后立即提交。

插件部分只进 `preview` 渠道（`npm run build:preview`，产物为 `bella-live-clip.preview.user.js`），公开版行为不变。本计划按创作台已经完成的状态来设计。

### 以后（本期不做，只保证不冲突）

- 认领；相近轴自动归组；投稿模板；
- QQ 群 bot 记轴（OneBot）；
- BiliUploadAuto 作为整套系统的后端：识别字幕（阿里云语音识别、说话人分离、服务器上用声纹向量对应成员）；插件下指令，服务器压制字幕后调用创作台投稿；
- AI 自动切片。

## 3. 设计原则

1. **唯一视频源是 B 站回放。** 所有人面对同一条时间线。
2. **轴只记原始 UTC 时间。** 记录时不关心是哪一场、哪个分 P，需要跳转时再换算成回放位置。以后 bot、网页或 AI 产生的轴也用同一种数据。
3. **所有投稿都走创作台。** 组织账号 cookie 只存在创作台服务器上，插件只拿到单个文件的临时上传凭证。
4. **新功能只进预览版。** 公开版不受影响。

## 4. 已测得的事实

### 4.1 直播中的回放（2026-11-09 实测）

测试对象是直播间 30858592，在直播进行中测了约 30 分钟。

- **延迟：** 回放比直播源最前沿晚 3 到 13.5 秒，中位数 8 秒，不是原先估计的 40 秒。新分片大约每 10 秒到一批，每批 2 到 3 个。
- **`GetUserSliceStream` 返回固定快照：** `end_time` 是「截至此刻已录到的位置」，比请求时刻早 2 到 15 秒；请求未来的时间会被截断。它签发的播放列表是固定的 VOD（带 `#EXT-X-ENDLIST`），不会自己增长。**要看到新画面，必须重新调用 `GetUserSliceStream`。**
- **本场回放不在 `GetOtherSliceList` 里。** 插件已经通过 `getRoomBaseInfo` 获取当前场次，不受影响。
- **分片：** 中位数 4.17 秒，实际在 1.02 到 4.98 秒之间。每个分片都能独立解码（`ftyp moov moof mdat`），以关键帧开头。
- **时间线：** 直播源和回放用同一条媒体时间线，各自编码。13 分钟内媒体时间和真实时间同步，没有漂移。
- **分片地址会迁移：** 最新约 90 秒的分片先放在 `/live-bvc/` 路径，一两分钟后迁到正式录像路径。旧地址仍然可用，所有地址签名 60 天有效。
- **未测到：** 直播中途断流时如何产生新的分 P。

### 4.2 时间换算（2026-11-03 实测，直播中复核）

- 在每个分 P 内：**平台 Unix 时间 = 分片媒体时间（tfdt）+ 常数 origin**。
- 请求完整分 P 时，origin − 分 P 的 `start_time` 约为 +0.5 秒（−0.1 到 +0.98 秒）。这对应观众播放器落后直播最前沿约 2 秒时看到的画面；直播最前沿本身约为 `start_time` − 1.75 秒。
- 只请求分 P 中间一段时，`start_time` 会被截成请求的起点，所以 origin 必须用完整分 P 的请求来确定。
- 断流后每个分 P 要单独确定 origin。不能用 EXTINF 累加计时，长场次会漂移 8 到 23 秒。

弹幕压制已经在使用这套换算。

### 4.3 网络

从当前这台海外服务器连接 B 站国内 CDN（`d1--cn-*.bilivideo.com`），建立连接需要 1.5 到 11.5 秒，并且经常握手超时。本期视频都由插件在用户浏览器里拉取，不受影响。以后服务器端压制字幕前，要先在目标服务器上实测。

## 5. 整体结构

```text
┌──────────────────── 贝报切片助手（预览版） ────────────────────┐
│ 记轴 ─▶ 轴表（每 10 秒刷新）─▶ 跳转/预设选区 ─▶ 投稿（导出+上传+填写并行） │
└──────┬─────────────────┬─────────────────────────────┬─────────┘
       │ 插件令牌          │ 轴的读写                      │ 分片直传（不带 cookie）
       ▼                 ▼                             ▼
┌──────────────── 贝报创作台 ────────────────┐      B 站上传节点
│ 插件令牌 · 轴与变更历史 · 轴页面 · 投稿内核 │──提交稿件──▶ B 站
└───────────────────────▲────────────────────┘
                        │ OIDC 登录
                bellaris-accounts
```

## 6. 登录：插件令牌

accounts 只支持 confidential 客户端，用户脚本里藏不住 client secret，所以插件不直接做 OIDC。

1. 插件里点「登录」，打开创作台的 `/plugin/link`；
2. 如果没登录，创作台走现有的 accounts 登录流程；
3. 页面以同源请求（带会话 cookie）向创作台申请插件令牌；
4. 切片助手本来就作为上传桥运行在 `studio.bk0717.com` 上，在这个页面上用 `GM_setValue` 保存令牌。这个值和插件在 B 站页面里读到的是同一份；
5. 之后插件在 B 站页面上用 `GM_xmlhttpRequest` 加 `Authorization: Bearer <令牌>` 调用创作台。

**令牌规则：**
- 只能访问轴和投稿相关的接口；
- 数据库只存哈希；
- 有效期 30 天，使用时自动续期；
- 用户可以在创作台查看和吊销自己的令牌；
- 成员离队或被封禁时，随会话一起吊销。

插件设置里显示当前登录身份，也就是 accounts 里的显示名，并提供退出入口。不登录也能用插件原有的切片功能；记轴、轴表和投稿需要登录。

## 7. 轴

### 7.1 数据

当前状态表 `marks`：

| 字段 | 说明 |
| --- | --- |
| `id` | UUID，由客户端生成，离线补传时用来去重 |
| `room_id` | 直播间号，由插件从当前页面读取（联动时可能是其他成员的直播间） |
| `at` | UTC 时间，毫秒 |
| `note` | 备注，可以为空 |
| `bvid` | 关联的稿件，可以为空 |
| `deleted` | 是否已删除（软删除） |
| `created_by` / `created_at` | 记轴人、创建时间 |
| `updated_by` / `updated_at` / `rev` | 最后修改人、修改时间、版本号 |

变更记录表 `mark_revisions`，类似 git 的提交记录：只增不改，每次新建、修改、删除、恢复都追加一条。

| 字段 | 说明 |
| --- | --- |
| `mark_id`、`rev` | 第几个版本 |
| `op` | `create` / `update` / `delete` / `restore` |
| `changes` | JSON，每个变动字段的旧值和新值 |
| `by`、`at_time` | 修改人、修改时间 |

`marks` 和 `mark_revisions` 在同一个事务里写入。

### 7.2 规则

- 所有组员都能编辑、删除任何一条轴。
- 并发修改用版本号判断：提交时带上 `rev`，不一致就返回冲突，插件刷新后让用户重试。
- 相近的轴平铺显示，不自动合并。
- 暂不做认领。投稿成功后把 BV 号写到对应的轴上，大家就能看到哪条已经切过了。

### 7.3 记轴的时间

- 记的是**按下记轴那一刻的 UTC 时间**，不在记录时扣除观看延迟。
- 插件每次调用创作台时，用响应的 `Date` 头或专门的时间接口估算本机时钟偏差，记轴时间按偏差校正。这样可以避免组员电脑时间不准。
- 网络不通时，轴先存在本地（`GM_setValue`），恢复后用客户端生成的 `id` 补传，不会重复。

### 7.4 插件里的操作

- **快捷键记轴：** 面板关闭时也能用。按下后立即记下时间，弹出一个小输入框填写备注，回车保存；不填也能保存，以后再补。具体按键在实现时确定，要避开现有的 `Alt+Shift+C`。
- **补记：** 输入 `21:13 跑调` 或 `21:13:40 跑调`，按东八区时间解析，日期默认为当天，跨零点时取最近一个过去的时刻。
- **轴表：**
  - 列出当前直播间、当前这场直播时间范围内的轴，按时间排序，显示东八区时间、备注、记轴人、BV 号；
  - 面板打开时每 10 秒刷新一次；
  - 可以直接修改备注和时间、删除，以及查看变更历史。
- **跳转：** 点击一条轴，把选区设为 `[at − 30 秒, at + 15 秒]`，并跳到入点。余量可以在设置里修改。
- **刚记的轴：** 回放还没覆盖到的轴显示「等待回放」，通常十几秒后变为可用。插件需要重新调用 `GetUserSliceStream` 获取新画面，不能只刷新旧的播放列表。

### 7.5 东八区时间到回放位置的换算

把弹幕压制里已有的换算抽成独立模块，提供两个函数：
- `UTC 时间 → (分 P, 回放位置)`；
- `(分 P, 回放位置) → UTC 时间`。

origin 用完整分 P 的请求确定，并按分 P 缓存。落在断流空档里的时间，对齐到最近的有效画面，并提示用户。以后服务器端（BiliUploadAuto）要用同样的规则，测试数据也共用。

### 7.6 创作台的轴页面

- 按日期和直播间筛选，按时间列出轴，显示记轴人、备注、BV 号；
- 可以新建、编辑、删除、恢复，查看每条轴的变更历史；
- 「复制为文本」：输出 `21:13 跑调` 这种格式，方便贴到群里。

## 8. 投稿

### 8.1 流程

```text
点击「投稿」
  ├─ 后台：导出 ──▶ 向创作台申请上传凭证 ──▶ 分片直传 B 站上传节点
  └─ 前台：填写标题、标签、封面（简介、类型、合集自动填好）──▶ 点「确认」
                        │
       上传完成 并且 已确认 ──▶ 立即调用创作台提交 ──▶ BV 号写回对应的轴
```

- 填写和导出、上传同时进行。哪边先完成都可以，两边都完成后立即提交。
- 提交前随时可以取消：停止导出和上传，已上传的分片不会变成稿件。
- 提交由创作台的投稿内核完成，沿用它的频率限制、遇到 601 即暂停、响应丢失时先核对再重试等保护。
- 直传失败时，回退到创作台已有的 COS 中转路径。
- 上传从导出产生的临时文件（OPFS）分片读取，不整个读进内存；投稿完成或取消后再清理临时文件。
- 如果是从某条轴开始切的，投稿时带上轴的 `id`，成功后写回 BV 号。

### 8.2 稿件信息

| 项目 | 规则 |
| --- | --- |
| 标题 | 投稿人填写 |
| 标签 | 固定标签加上投稿人手动添加的标签 |
| 简介 | 直播名、直播日期，末尾写 `视频二创组----<投稿人显示名>` |
| 类型 | 自制 |
| 合集 | 自动加入创作台配置的「当前切片合集」；满了以后在服务器端换，插件不用改 |
| 封面 | 见 8.3 |

- 直播名和直播日期从日程 ICS 读取（插件已经在用日程）。用排期日期，跨零点的直播也不会写错日期。日程里找不到对应场次时，回退到开播时间和直播标题。
- 投稿人显示名取自 accounts，创作台登录时已经保存了这个名字。
- 固定标签、简介格式、当前合集都存在创作台配置里，插件读取，以后改成模板。

### 8.3 简单封面

- 从切片里挑一帧，默认取选区中点，可以拖动换帧；
- 按 B 站封面比例裁剪；
- 可以加一行文字，调整字号、颜色、描边和位置。GIF 助手里已经有文字图层的代码，可以参考。

## 9. 需要新增的接口（创作台）

接口路径是草案，以实现时为准。

| 接口 | 用途 |
| --- | --- |
| `GET /plugin/link` | 插件令牌领取页面（会话登录） |
| `POST /api/plugin-tokens`、`GET`、`DELETE /api/plugin-tokens/{id}` | 签发、列出、吊销插件令牌（会话登录） |
| `GET /api/time` | 服务器时间，用于校正时钟 |
| `GET /api/marks?room_id=&from=&to=` | 按直播间和时间范围查询轴 |
| `PUT /api/marks/{id}` | 新建或修改轴（带 `rev`，冲突时返回 409） |
| `DELETE /api/marks/{id}`、`POST /api/marks/{id}/restore` | 删除、恢复 |
| `GET /api/marks/{id}/revisions` | 变更历史 |
| `GET /api/clip-defaults` | 固定标签、简介格式、当前合集、分区 |
| 现有投稿接口 | 增加 Bearer 令牌认证；提交时可以带 `mark_id` |

## 10. 实施顺序

每一步都能单独验证、单独上线。

1. **创作台：插件令牌。** 令牌表、签发和吊销、`/plugin/link`、Bearer 认证。
2. **插件：登录。** 在 `studio.bk0717.com` 上领取并保存令牌，在 B 站页面调用 `/api/me` 验证；校正本机时钟。
3. **创作台：轴。** `marks`、`mark_revisions`、接口和轴页面。
4. **插件：记轴和轴表。** 快捷键记轴、补记、离线补传、轴表、10 秒刷新、编辑、历史。
5. **插件：换算模块和跳转。** 抽出换算模块，点击轴跳转并预设选区，处理「等待回放」。
6. **插件：投稿。** 投稿面板、导出与上传并行、确认后提交、取消、回退 COS、写回 BV 号。
7. **插件：简单封面。**

做完第 5 步，「找片段」就消失了；做完第 6 步，整个流程就跑通了。
